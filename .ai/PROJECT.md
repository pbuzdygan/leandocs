# Project Profile

LeanDocs — a lightweight, self-hosted, filesystem-first Markdown documentation manager. Single owner; built mostly by AI coding agents under the owner's direction.

## Required

- Goal and scope: [`PROJECT_SPEC.md`](../docs/PROJECT_SPEC.md) (what the app does) and [`UI_SPEC.md`](../docs/UI_SPEC.md) (how it looks and behaves). Features in PROJECT_SPEC §99 stay out of scope unless the owner explicitly changes it. Release state: [`CHANGELOG.md`](../CHANGELOG.md).
- Required verification: `pnpm format:check && pnpm lint && pnpm typecheck && pnpm test && pnpm build` (CI runs the same plus `pnpm audit --audit-level=moderate`, browser tests and a Docker build: `.github/workflows/ci.yml`). Run the browser tests (`pnpm test:e2e`) for UI, routing, auth or editor changes, and `pnpm test:performance` for indexing, scanner, link rewriting, import or attachment changes; commands and the Playwright container are in [`docs/development.md`](../docs/development.md#tests). A feature is done only when it meets PROJECT_SPEC §101.
- Protected resources and unsafe commands: the owner's `data/` (real documentation, `system/app.db`, `auth.initialized`, `mfa.key`) and `.env` — never modify or use them in tests; use the disposable `.e2e/` folder or temp directories. Releases and image publishing are the owner's: never create release tags or GitHub releases. Never edit a database migration that shipped in any release, including `devX.Y.Z` releases ([`docs/migrations.md`](../docs/migrations.md)); add a new one. Do not push, open PRs or rewrite shared history unless asked.

## Project constraints

- **Precedence:** PROJECT_SPEC (its rules in §105) and accepted ADRs in [`docs/adr/`](../docs/adr/) define the architecture; UI_SPEC and [`BRAND_SPEC.md`](../docs/BRAND_SPEC.md) define the UI and branding. [`UI_DESIGN_GUIDELINES.md`](UI_DESIGN_GUIDELINES.md) is a generic fallback only for questions these do not answer. Do not change the UI direction without an owner decision.
- **Architecture invariants** (never change without an owner decision and an ADR): the filesystem is the source of truth and canonical content lives only in `.md` files; SQLite is a rebuildable index plus durable app data (accounts, settings, pins); one container, no extra services; never assume LeanDocs is the only process changing documents; never weaken Markdown/HTML/Mermaid rendering security; keep users' files byte-for-byte except for the documented minimal edits.
- **Branding:** name, tagline and wordmark only from `APP_NAME` / `APP_TAGLINE` / `APP_WORDMARK` in `packages/shared`; in the UI use `AppLogo`, `Wordmark` and the `--brand-*` / `--accent` tokens. Brand exports are generated by `branding/tools/`; do not edit them by hand.
- **Language:** everything written to the repository (code, comments, docs, UI strings, commits) is English, even when the owner writes in Polish.
- **Decisions:** ADRs go in `docs/adr/` (template `0000-template.md`), smaller decisions, open owner questions and accepted known issues in [`docs/decisions.md`](../docs/decisions.md). Plans that must survive a session go in `.ai/plans/`.
- **Documentation:** when user-visible behaviour changes, update the matching user guide (`docs/{deployment,configuration,import,markdown,attachments}.md`) and add a `CHANGELOG.md` entry following [`CONTRIBUTING.md`](../CONTRIBUTING.md#changelog). Never write "comes in Phase N" or similar roadmap promises into user docs.
- **Git:** work on `dev` (tracks `origin/dev`, `https://github.com/pbuzdygan/leandocs.git`) or a short-lived branch; `main` receives `dev` through pull requests. Conventional Commits with scopes `server`, `web`, `shared`, `docs`, `ci`, `docker`, `repo`. Never commit `data/`, `.env`, `node_modules/` or test output.
- **Dev machine:** 12 GiB RAM, 4 CPUs and 4 GiB swap (since 2026-10-16; before that 6 GiB without swap). Run browser tests in the Playwright container with `--memory 2g --cpus 2` (an unlimited run once froze the old machine); local Chromium lacks system libraries. A local Docker image build is fine on this machine.
